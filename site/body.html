This works it out from the accession alone, and shows what it did at every step — so an expert can check it rather than take its word.

In plain terms

The question. A new virus turns up. Which of its proteins should a drug aim at? Picking that target is normally expert judgement — reading the literature, and comparing the new virus to ones that are already understood.

What this does. It takes one accession number — the public database ID for a genome — and nothing else. From that it works out which proteins the virus makes, ranks them by how promising a drug target each one looks, predicts one protein's 3-D shape, and checks whether a drug would have anywhere on it to grip. Shape first, because for a virus nobody has studied there is no solved structure to look at, and a predicted one is the only thing left to measure. Five steps, about a minute and a half, with no person naming the target.

The test below. It was given SARS-CoV-2 — with SARS-CoV-2 itself removed from everything it was allowed to look up, so it could not simply recognise the answer. It still put the real drug targets at the top, including the one an approved antiviral already hits.

Run it on your own pathogen

One nucleotide accession is the whole input. No target name, no shortlist, no structure. The same five steps you just read run against the same live databases, and the result becomes a page like this one.

Open the request form

For a genome split across segments, separate the accessions with commas. A genome too large to be viral is refused rather than ranked: this is antiviral work, and the reference it identifies against is reviewed viral proteins.

From a genome to a ranked shortlist

Five steps, run live against public databases. Everything below this line is the path to the deliverable: a list of candidate targets, ranked, with every score decomposed and every surface either measured on a deposited structure, computed on a predicted one, or refused with a reason.

The {{orfs_ranked}} it ranked, and why each one scored what it did

Those counts are what this step reports. Below is what it actually returned. Nothing is fetched from an existing annotation of this genome: the sequence is translated in all six reading frames, every stretch between stop codons of at least {{minimum_orf_aa}} residues is kept — overlaps in different frames included, because discarding one of two overlapping frames here would let length decide what homology should — and the {{orfs_ranked}} longest are searched against {{reference_entries}} reviewed viral proteins with SARS-CoV-2 itself deleted from that reference. Identification is tried in three tiers, cheapest first: exact 5-mer identity, then reduced-alphabet seeding with Smith–Waterman where that finds nothing, then hydropathy, which returns a class rather than a name and is scored so it cannot outrank a real homology hit.

Two things worth reading off the columns rather than the scores. The spike and the replicase finish within a few hundredths of each other and get there by opposite routes — the spike earns the full exposure term and little conservation, the replicase the reverse — so they are a near-tie between an antibody target and a target only a cell-permeable drug reaches. And the conservation column is the only one measured against this genome; the other four are read off whichever relative was matched, which is why holding the pathogen out lowers the scores instead of emptying the list.

The toolkit

Ten tools in all, each calling live public biology databases. Four of them are called by the five steps above, and section 04 details every call those steps made — the second step's two, intake.decompose and intake.rank_score, are functions in the same module rather than separate registered tools. The rest are reachable from the same four facts step 1 produces, and were exercised separately to record what they cost and how they fail. Deliberately bad inputs are included, so each failure mode is on record rather than assumed.
